# 从部署到模型调用

MiniStation 将常用配置整合到现有“服务部署”和“分布式推理”页面，保持单控制面、少量依赖的轻量部署方式。

## 轻量导航与服务详情

主导航保留“运行总览、模型资产、服务部署、在线调试、监控告警、平台设置”六项。相关功能在页面顶部切换：

| 主入口 | 常用功能 | 按需展开 |
| --- | --- | --- |
| 模型资产 | 模型资产、部署模板 | — |
| 服务部署 | 服务部署、接入服务、服务目录 | 分布式推理、服务编排、发布管理、弹性伸缩、原生资源 |
| 在线调试 | 在线调试、访问密钥 | — |
| 监控告警 | 监控告警、服务指标、用量账本、任务记录 | — |
| 平台设置 | 平台设置 | 资源池与容量、项目策略、集群节点、操作审计；按角色展示 |

原页面地址仍可直接访问。服务行的“服务详情”集中运行状态、诊断、日志与接入发布；修订、停止、清单等在“更多操作”。普通修订直接编辑镜像和资源，启动命令/参数折叠为高级配置。无日志权限的角色不显示日志操作。

## 大模型部署向导

1. 打开“服务部署 → 大模型部署”。向导先检测目标推理集群；可选择项目允许的资源池，切换后重新检测，不沿用旧推荐。
2. 查看环境结果和推荐依据。未接入、不可观测、无 NVIDIA GPU、配额不足、无可调度容量分别提示，不会自动增加配额或将 GPU 引擎改成 CPU 引擎。
3. 选择 vLLM / SGLang 基础模板，也可展开“复用已验证的部署模板”。已验证模板来自当前项目曾就绪的服务，会显示当前容量、策略、配额和模型卷检查结果；使用模板不会自动改写其资源。
4. 填写镜像摘要、部署名、服务模型名和模型目录，从当前命名空间选择已绑定模型卷。无法读取卷列表时，可展开“高级模型配置”手工填写 PVC；仍需通过预检。
5. 推荐资源自动填入，默认折叠 CPU、内存、GPU、TP 与共享内存。需要调整时展开“高级资源配置”；点击“恢复推荐参数”放弃自定义资源。重新检测环境会重新计算资源并清除旧预检结果。
6. 检查配置时优先展示未通过项，全部检查和启动参数放在折叠区。保存草稿不创建集群资源；实际部署仍重新检查配额、策略和清单。

模型只读挂载到 `/models`，需预先准备文件。关联模型资产仅用于追溯，不自动复制本地快照到卷。基础模板为单节点、单副本 GPU 文本对话，TP 必须等于 GPU 数。镜像需支持 UID 1000 非 root 运行。

## 环境感知与推荐边界

推荐读取目标 Kubernetes 节点 allocatable、当前 Pod requests、就绪/禁止调度状态、污点、资源池标签和项目剩余配额。不会拿控制台所在 Windows/WSL 机器的资源代替目标节点资源。

保守起点为单卡、TP 1、共享内存 0.5 GiB；CPU 最多 4 核、容器内存最多 16 GiB，同时受**单个候选节点**剩余资源、项目剩余配额、项目策略上限约束。剩余资源不足时不拼接多节点零散容量；不满足基本条件时不推荐。副本、进行中的伸缩资源预占与分布式组申请量计入项目余量。

硬件信息可显示节点架构，以及节点标签提供的 NVIDIA GPU 型号/单卡显存；缺失时显示未知。它们是标签信息，不是设备实测认证。当前不估算具体模型权重/KV Cache 显存，不认证驱动与引擎兼容性，不声称性能最优。容量快照不会预留资源，集群中的其他任务仍可能改变调度条件。

无 GPU 时优先引导接入远程模型，或复用已有 CPU 模板；不自动修改 GPU 推理引擎。PD 仍需显存、网络和负载测量，不因卡数足够就推荐启用。分布式配置可选择节点和模型卷，手工节点名称、资源、标签等放入高级部署配置。

## 接入与发布

管理员在已创建集群资源的服务行，或分布式模型组行，点击“接入与发布”：

1. 自动填写部署关联、Service 地址及 `--served-model-name`；分布式组使用组服务模型名。手工部署无法识别模型名时需要填写。部署尚未就绪时提示先同步状态。
2. 确认协议与控制面可访问的 Base URL，按需填写引擎认证 Key。集群 DNS 地址仍必须在 `MINISTATION_UPSTREAM_HOSTS` 中明确授权；本地开发可以使用已配置的端口转发地址。向导不会开放网络白名单。
3. 点击“接入此部署”，创建未验证后端。若已有接入记录，继续使用已有记录；多个记录可选择，不自动覆盖地址或凭据。
4. 执行真实连接测试。只有返回有效协议响应后才能发布；测试会调用模型，可能产生上游费用。失败后在“接入服务 → 编辑”修正地址或认证，再重试。
5. 发布逻辑模型后，在“访问密钥”创建授权 Key，再到“在线调试”调用。对外请求中的 `model` 使用发布名。

默认费率为 0，可在“接入服务 → 编辑”设置。启用的发布路由显示已有发布状态，避免重复创建；更改已发布后端继续遵循原有排空、下线与重新验证规则。

## 部署诊断

“服务部署 → 服务详情 → 诊断”显示问题、Pod/事件依据及建议操作，涵盖镜像拉取失败、普通容器和初始化容器异常、OOMKilled、调度不足、模型卷挂载和健康探针失败。原始 Pod 状态与事件保留在折叠区。

诊断仅提供建议，不自动修改资源。历史 OOM 或探针事件可能已恢复；未识别到常见故障不等于模型可用。容器 OOMKilled 表示容器内存问题，不能直接认定为 GPU 显存不足。仍需结合“运行状态”、日志和连接测试判断。

## 验证边界

单元及 API 测试覆盖配置生成、拒绝非法参数、预检失败、项目和角色隔离、实际本地 HTTP 协议探测与发布门禁；浏览器覆盖向导、输入失效、接入引导、诊断与移动布局。两种引擎的 Deployment/Service 已通过真实 Kubernetes dry-run。当前环境没有 GPU，尚未验证这些镜像的真实模型加载、推理性能或硬件兼容性。
