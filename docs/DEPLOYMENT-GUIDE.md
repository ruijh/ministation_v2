# 从部署到模型调用

MiniStation 将常用配置整合到现有“服务部署”和“分布式推理”页面，保持单控制面、少量依赖的轻量部署方式。

## 大模型部署向导

1. 打开“服务部署 → 大模型部署”，选择 vLLM 或 SGLang。
2. 填写固定摘要的镜像、当前项目模型 PVC、容器内模型目录和服务模型名。模型卷只读挂载至 `/models`，模型文件需提前准备；关联模型资产仅用于追溯，不会自动将本地快照复制到 PVC。
3. 设置 CPU、容器内存、GPU、TP 和共享内存，可选择项目资源池。此基础模板为单节点、单副本 GPU 文本对话，TP 必须等于 GPU 数。共享内存挂载至 `/dev/shm`，占用容器内存，需为模型加载保留余量。
4. 点击“检查配置并预览”。检查镜像摘要、项目配额和策略；已配置集群时，还检查模型卷 Bound 状态、节点剩余 requests、标签、污点及 Kubernetes 服务端 dry-run。容量不可观测时明确显示待处理，不将未知视为通过。
5. 保存草稿，再从列表点击“部署”。保存草稿不会创建集群资源，部署时重新执行现有配额、策略与服务端校验。修改向导输入会清除旧预检结果。

项目要求的标签自动加入生成配置。参数为基础启动组合，不是模型显存估算或性能最优参数。镜像需要包含对应引擎并支持 UID 1000；模型架构必须支持选定 TP。预检不读取卷内模型、不加载模型、不预留容量，也不保证最终调度成功。

“使用手动配置”可处理自定义参数、向量模型和其他镜像；多节点 TP 与 PD 使用“分布式推理”。原有“部署模板”仍用于复用已就绪服务的固定配置，包含共享内存设置。

## 接入与发布

管理员在已创建集群资源的服务行，或分布式模型组行，点击“接入与发布”：

1. 自动填写部署关联、Service 地址及 `--served-model-name`；分布式组使用组服务模型名。手工部署无法识别模型名时需要填写。部署尚未就绪时提示先同步状态。
2. 确认协议与控制面可访问的 Base URL，按需填写引擎认证 Key。集群 DNS 地址仍必须在 `MINISTATION_UPSTREAM_HOSTS` 中明确授权；本地开发可以使用已配置的端口转发地址。向导不会开放网络白名单。
3. 点击“接入此部署”，创建未验证后端。若已有接入记录，继续使用已有记录；多个记录可选择，不自动覆盖地址或凭据。
4. 执行真实连接测试。只有返回有效协议响应后才能发布；测试会调用模型，可能产生上游费用。失败后在“接入服务 → 编辑”修正地址或认证，再重试。
5. 发布逻辑模型后，在“访问密钥”创建授权 Key，再到“在线调试”调用。对外请求中的 `model` 使用发布名。

默认费率为 0，可在“接入服务 → 编辑”设置。启用的发布路由显示已有发布状态，避免重复创建；更改已发布后端继续遵循原有排空、下线与重新验证规则。

## 部署诊断

“服务部署 → 诊断”显示问题、Pod/事件依据及建议操作，涵盖镜像拉取失败、普通容器和初始化容器异常、OOMKilled、调度不足、模型卷挂载和健康探针失败。原始 Pod 状态与事件保留在折叠区。

诊断仅提供建议，不自动修改资源。历史 OOM 或探针事件可能已恢复；未识别到常见故障不等于模型可用。容器 OOMKilled 表示容器内存问题，不能直接认定为 GPU 显存不足。仍需结合“运行状态”、日志和连接测试判断。

## 验证边界

单元及 API 测试覆盖配置生成、拒绝非法参数、预检失败、项目和角色隔离、实际本地 HTTP 协议探测与发布门禁；浏览器覆盖向导、输入失效、接入引导、诊断与移动布局。两种引擎的 Deployment/Service 已通过真实 Kubernetes dry-run。当前环境没有 GPU，尚未验证这些镜像的真实模型加载、推理性能或硬件兼容性。
