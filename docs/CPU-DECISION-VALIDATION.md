## 使用判断

可以作为真实 CPU 模型的部署、接口、治理和编排验证基线。当前 checkpoint / 读取方式在本样本中的技术类区分能力不足，不建议作为无人兜底的通用中文工单路由。后续优化需要使用独立验证集，比较更大模型、针对任务训练的分类器或校准后的选项读取；不能在本100条样本上调参后继续称其为独立验收结果。

- 三个 kind 节点均导入固定镜像摘要 `sha256:679305aec808924053bff86f022ce4451a57db310ee5a82949b61ff4abfc7bf9`。
- Deployment `ms-2605a22e`：1/1 Available；2 CPU、4 GiB、0 GPU；非 root 用户；模型随镜像离线加载。
- 模型 Pod 首次验收无重启、无 OOM；健康检查在权重加载后通过。
- 已发布逻辑模型 `jev-cpu-qwen3-0.6b`，协议 `decision`。
- 使用本轮代码创建的临时控制面实例，通过真实平台 Key 调用成功，退款样本选择 billing；输入107 Token、输出0 Token，账本状态 settled，单次网关耗时863 ms。
- 验收 Key 已撤销、临时管理员会话已删除；模型服务保留供控制台使用。
- 本机转发由 `ministation-jev-forward.service` 管理，端口8801。

并发导入三份大镜像曾造成单机磁盘压力，导致 kube-controller-manager 和 scheduler 租约续期超时退出。导入完成后重启控制节点 kubelet 以恢复重试，控制面恢复 Running、部署变为 Available。构建脚本已改成逐节点导入，降低后续重复操作的并发 I/O 压力；该顺序导入变更未重新导入大镜像验证。

8787端口的旧控制台进程由更高权限启动，Windows拒绝当前会话终止它。新版网关已通过独立实例验证，但原端口启用新代码仍需在原启动窗口停止旧服务，再运行 `scripts/start-local.ps1`。
