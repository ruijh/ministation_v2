# 资源治理、发布保护与弹性伸缩

MiniStation 提供资源治理、发布保护与弹性伸缩。所有配置继续按项目隔离，修改操作沿用角色、CSRF、审计与乐观锁。没有为用户现有部署默认开启灰度或自动伸缩。

## 功能范围

| 功能 | MiniStation 实现 |
| --- | --- |
| 资源池 | 项目内节点标签分组，复用 Kubernetes 默认调度；没有专用资源池调度器 |
| 部署策略 | 镜像主机允许列表、资源池约束、资源上限、必填标签、默认资源 |
| 监控、伸缩 | CPU/内存/GPU 数据适配、控制台告警、CPU/并发伸缩 |
| 灰度、自动回退、SSE 排空、备用切换 | 稳定/候选后端路由、指标门槛、在途请求计数与排空 |

## 资源池与策略

“资源池与容量”创建项目资源池；选择标签必须匹配节点已有标签。池定义不可原地修改，避免改变已部署服务的调度语义；需要新标签时创建新池。删除受部署、模板和策略引用保护。不同池可以重叠，容量不能简单相加。

容量显示项目配额、节点 allocatable、全命名空间 Pod requests 和剩余申请空间。考虑普通容器、初始化容器、常驻初始化容器、Pod 级资源及 overhead；终止的 Pod 不计入。剩余空间不保证可调度，仍受污点、拓扑、资源碎片等约束。缺少全局 Pod 读取权限时剩余值为不可用。

“项目策略”只由管理员修改，默认值只填充未提供字段。策略校验同时覆盖创建、预检、提交、修订、回滚、自动伸缩和原生 YAML；原生多容器会校验有效总资源，不能通过拆分容器绕过每副本上限。原生工作负载使用 Pod 模板 annotation `ministation.io/pool-id` 指定池，nodeSelector 仍须与池匹配。现有工作负载不会因修改策略被自动终止。

## 监控与发布

“监控告警”显示每部署实际 CPU 核数、内存 GiB、CPU/内存相对申请量的百分比和 GPU 平均利用率。优先查询管理员通过 `MINISTATION_PROMETHEUS_URL` 配置的 Prometheus：

- CPU：按 namespace、pod 汇总 `rate(container_cpu_usage_seconds_total[2m])`。
- 内存：按 namespace、pod 汇总 `container_memory_working_set_bytes`。
- GPU：带 namespace、pod 标签的 `DCGM_FI_DEV_GPU_UTIL`。

没有 Prometheus CPU/内存完整样本时使用 Metrics Server 近期快照，不提供硬件历史时序库。Metrics Server 官方定位为自动伸缩数据源；生产历史监控应接入 Prometheus。GPU 不会从 CPU 指标推算，也不会把未配置显示成 0。采样过期或缺失会阻止相应自动伸缩。

支持错误率、P95、服务不可用、CPU/内存/GPU 阈值告警。状态为 Pending、Firing、Resolved、Unknown、Disabled，支持连续次数、请求最少样本、时间窗口、禁用及知晓确认。状态变化保留审计；告警显示在控制台，并支持可选通用 Webhook 通知；配置见 [通知指南](DELIVERY.md)。

“发布管理”支持直接后端路由的候选流量百分比、提升候选、回退稳定版。候选与备用后端必须同项目、同协议且完成验证。灰度按请求 ID 确定性分配；有限样本中的比例不保证恰好相等。自动回退只使用本次灰度开始后的候选后端样本，达到最少样本后按错误率/P95 阈值将候选流量归零。

备用切换只在上游明确返回 HTTP 429、502、503、504 且尚未向客户端发送内容时发生，最多两个备用后端。网络错误、超时、401/403、协议错误和已开始的 SSE 不会自动重放。每次尝试保存在 traffic_attempts，最终响应按实际后端计量；失败尝试没有 usage，不能宣称已完成其供应商账单核对。

排空先拒绝新请求，等待已有请求（含 SSE）结束，再下线。等待超时保留排空状态，可继续排空或取消。不会强行截断已有流。部署停止/删除会检查在途请求和稳定/候选/备用引用。

## 弹性伸缩

“弹性伸缩”按部署配置：CPU 使用率或每副本在途请求数、目标值、最小/最大副本、冷却期及连续低负载次数。保存默认为禁用，需要明确勾选启用。

控制面默认每轮结束 15 秒后再评估。CPU > 目标的 110% 时按比例扩容；低于 70% 连续满足指定次数后每次缩减一个副本。最小副本不低于 1；没有实现缩到零或自定义指标插件；请求队列在平台设置中独立配置。

变更前需要新鲜就绪观测、资源池/项目策略和配额预检，写入使用 Kubernetes resourceVersion，留存修订和审计。扩容期间预占平台资源额度；缩容会短暂阻止关联路由的新请求，并等待平台内在途请求排空，最多 30 秒。指标缺失、配置偏差、配额不足或排空超时保持原副本并记录原因。

排空只覆盖经过 MiniStation 网关的请求，直接访问模型 Service 的客户端不在计数范围内。当前单控制面内存计数不支持多网关副本协调。进程重启保留中断记录并核对集群，不盲目重放伸缩写操作；中断后的配置偏差须通过修订/恢复处理。

## 本地环境与验收

本地 kind 已安装 Metrics Server v0.9.0。复现安装使用 `infra/wsl/Install-Metrics.ps1`，清单来源为 [官方 v0.9.0 发布](https://github.com/kubernetes-sigs/metrics-server/releases/tag/v0.9.0)。测试 overlay 的 `--kubelet-insecure-tls` 仅用于本地 kind 自签名证书，不适用于生产；生产应配置可信 kubelet 证书。基础 RBAC 新增只读 Pod 容量和 metrics.k8s.io 访问权限。

验证包括单元/HTTP 回归、浏览器流程、真实 Kubernetes CPU 模型与 2 → 3 → 2 副本伸缩。GPU/DCGM 使用协议测试验证解析，本机没有 GPU，因此硬件采集与性能未验收。没有将这些结果等同于 HA、分布式推理或完整企业生产验收。

更新后重启 `scripts/start-local.ps1` 对应的控制台进程以加载后端，并重新构建网页资源。
