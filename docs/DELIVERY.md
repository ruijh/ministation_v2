# 告警通知、请求排队与升级恢复

## Webhook 告警通知

管理员在服务进程设置 `MINISTATION_WEBHOOK_HOSTS`，以逗号分隔允许的主机名，不包含协议或路径。重启后进入“监控告警 → 外部告警通知”，填写名称、完整 URL 和至少 16 字符的共享签名密钥。地址与密钥加密保存，界面只显示主机；新渠道默认禁用。启用后接收当前项目后续告警，不回放历史告警。可以点击“发送测试通知”投递明确的测试事件。

只接受 HTTP(S)、不带用户凭据、查询参数或 fragment 的 URL；拒绝重定向。外部网络请使用 HTTPS。通用 JSON 格式不直接兼容飞书、企业微信机器人消息格式，可由接收端转接；专属模板与邮件渠道尚未提供。

首次进入 Firing 时产生 `alert.firing`，同一告警持续触发不会重复产生事件；恢复时产生 `alert.resolved`。暂时没有指标不会被误认为恢复。事务同时保存告警状态和投递记录；每个启用渠道独立投递。

请求头：

| 请求头 | 内容 |
| --- | --- |
| `X-Ministation-Event-Id` | 稳定的事件 ID，重试不改变 |
| `X-Ministation-Timestamp` | 当前 Unix 秒数 |
| `X-Ministation-Signature` | `sha256=` 加 HMAC-SHA256 十六进制摘要 |

签名原文为 `timestamp + "." + 原始 HTTP 请求体`，密钥为配置的共享签名密钥。接收端应校验时间窗口、使用恒定时间比较验证签名，再按事件 ID 持久去重。事件只含项目、规则名、指标、值与阈值，不含模型请求内容或凭据。

任何 2xx 表示成功。429、5xx、网络失败与超时重试；其他 HTTP 状态停止。单次超时 5 秒，总尝试上限 5 次；重试间隔依次约 20、40、80、160 秒。待投递记录持久化，重启后继续。进程可能在接收端成功后、记录成功前退出，因此是允许重复的投递协议，不保证精确一次。禁用会取消等待记录，已经发出的 HTTP 请求不能撤回。失败不自动无限重放，需接收端核对事件 ID 后处理。

界面显示最近 100 条记录，数据库保留历史记录；尚无自动归档。通知服务限单控制面实例，不支持多 worker 竞争领取。

## 项目请求队列

进入“平台设置 → 网关请求排队”。默认关闭，可配置最大在途请求 1–100、最大等待请求 0–100、等待时间 1–120 秒。所有项目合计最多 1000 个等待连接。修改配置要求该项目没有在途或等待请求。

队列覆盖 Chat、SSE、Embedding 和 Decision 调用，模型列表不排队。项目之间独立 FIFO；一个项目内不同 Key 和模型共享名额，不提供 Key 级公平调度。入队先校验 Key 与模型权限，出队由网关重新校验 Key、服务状态和预算；等待期间没有预算预占、没有上游调用，也不生成已结算 usage。撤销 Key 或下线模型后，等待请求不能绕过验证。

队满返回 429 `QUEUE_FULL`，等待超时返回 503 `QUEUE_TIMEOUT`。客户端断开会移出等待队列，SSE 在结束或断开后释放在途名额。响应中的 `X-Queue-Wait-Ms` 表示入队至进入网关处理的等待时间。RPM/TPM 在实际进入网关时校验，排队不承诺一定执行。网关账本延迟从进入执行器计算，等待时长单独通过响应头提供。

队列和计数在内存中，重启会断开等待连接且不会回放请求；不支持多网关共享队列、跨进程限流或持久任务队列。请求队列与部署缩容排空分别控制，缩容排空期间出队请求仍可能被部署保护拒绝。

## 升级与恢复演练

当前数据库结构版本为 2，`schema_migrations` 记录结构升级。现有版本 1 在新程序首次启动时通过事务升级；程序拒绝打开比自身更新的版本。升级前必须保留完整备份，回退时使用匹配的旧程序和旧备份，不要用旧程序直接打开升级后的数据库。

在项目根目录执行：

```powershell
node scripts/rehearse-recovery.mjs <现有数据目录> <不存在的演练目录>
```

命令在线备份源数据库及匹配的 master.key、登记模型快照，验证哈希后恢复到新目录，在恢复副本上执行迁移。检查 SQLite 完整性、外键、主要业务表记录数及凭据可解密性，生成 `report.json`。现有源数据不执行迁移、不覆盖、不启动集群或调用供应商。演练目录包含真实备份和可用凭据，须使用受控目录保存；Windows 的备份和恢复子目录设置当前用户及 SYSTEM 专用 ACL。

报告通过不等于应用或生产切换成功。切换前还需要登录验证、业务验收、Kubernetes 持久卷和外部模型恢复、目标网络与密钥权限检查。失败的演练目录留存诊断，不自动删除；重新演练使用新的目录。此工具不执行生产切换，不声称完成异机灾备或 RTO/RPO 验收。
