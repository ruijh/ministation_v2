# PD 分离部署（实验性）

MiniStation 提供 vLLM + NixlConnector 的 Prefill / Decode 分离编排。每个实例在单节点内做 TP，2–8 个不同节点组成 P/D 实例集合；同一模型组的实例使用相同 GPU 数、镜像、模型路径与服务模型名。首版不支持跨节点 TP 与 PD 嵌套、异构 TP、多模态、多个候选输出、跨轮 KV 复用或组级自动伸缩。

## 工作台操作

进入“工作空间 → 分布式推理 → 配置模型组”，选择“预填充与解码分离（PD）”。引擎固定为 vLLM。选择场景卡片后，可在“调整参数与资源取舍”修改参数，修改后标为“已自定义”。切换预设或修改表单会使已有预检结果失效。

填写互不重复的节点名称，前 N 个节点作为 Prefill，其余作为 Decode。每个实例均独立加载模型；只有实例内部的 TP 可以分摊模型显存，增加 P/D 实例数不会让一个模型跨这些实例拆分。模型卷须 Bound 且支持 ReadOnlyMany 或 ReadWriteMany。预检检查项目策略、总配额、节点容量、共享卷和 Kubernetes 服务端准入；它不能证明模型可加载或 NIXL 能通信。

需要两类摘要锁定镜像：推理镜像包含兼容 vLLM v0.31.0 接口的 NixlConnector、NIXL、UCX 和模型所需依赖；路由镜像提供 Node.js 24+ 的 `node` 命令。两类镜像必须支持 UID 1000 非 root 运行。路由器源码随 ConfigMap 挂载，无需 npm 安装。模型权重与 tokenizer 应来自同一不可变目录，不使用在线下载或任意远程代码。

## 场景预设与调优

以下数字是 MiniStation 提供的启发式起点，不是来自基准测试的最优参数；实际模型、GPU 显存、输入输出长度、并发、网络决定最终选择。

| 场景 | 起始拓扑 | 最大上下文 | P / D 批次 Token | 每实例序列上限 | 显存比例 | 观察与调整 |
| --- | --- | --- | --- | --- | --- | --- |
| 初次验证、均衡对话 | 1P1D | 8192 | 4096 / 2048 | 32 | 0.85 | 建立合并部署与 PD 对照基线，先确认正确性 |
| 长输入、文档问答 | 2P1D | 32768 | 8192 / 2048 | 32 | 0.85 | 观察 TTFT、P 排队及传输时间；P 瓶颈明确时增加 P |
| 长输出、持续生成 | 1P2D | 16384 | 4096 / 2048 | 64 | 0.85 | 观察生成间隔、D 排队及 KV 显存；D 瓶颈明确时增加 D |

模型必须支持指定上下文长度；超出模型配置会导致引擎拒绝启动。显存不足时优先降低上下文或序列上限，并检查模型权重占用。提高显存比例会减少运行余量。较大 P 批次并非总有利；短请求、低并发或网络较慢时，合并部署可能更合适。所有预设启用 chunked prefill，使用默认 KV 精度和同构 TP，避免未经认证的 KV 布局组合。

## 请求和资源行为

- 路由器为每次请求生成关联 ID，以非流式、单 Token 请求调用 P；只接受返回了 KV 传输元数据的成功响应，再调用 D。不会静默退化为两次独立推理，也不自动重试可能已执行的请求。
- P 使用 `kv_producer`，D 使用 `kv_consumer`，KV 加载失败策略为 `fail`。使用 Pod IP 发布 NIXL side-channel 地址，起始端口 5600。实际数据传输端口和网络需求取决于 UCX/NIXL 配置；必须保证可信 P/D Pod 互通。平台不自动挂载 RDMA 设备、开启特权或配置宿主网络。
- 内部入口支持 `/v1/chat/completions`、`/v1/models` 和 `/health`；首版仅支持文本 messages、n=1。客户端不得注入 KV 元数据或更换配置模型。流式输出保留 SSE 和 Decode usage，剔除内部 KV 元数据；Prefill usage 不另记入平台账本。账本显示逻辑请求用量，不表示两个阶段的实际 GPU 成本。
- 路由器以轮询方式选择 P/D，无故障重试；在途请求上限使用序列上限参数，超出返回 429。请求体限制 1 MiB，超时默认 120 秒，可调 10–600 秒；客户端断开会取消当前上游 HTTP 请求。失败或取消后的 KV 回收依赖引擎租约，不声称即时释放全部 GPU 内存。
- 路由器单副本固定请求 0.5 CPU / 0.5 GiB，位于首个 P 节点并计入容量及项目配额。P、D 和 router 都受镜像、标签、资源池策略约束。所有成员就绪才允许关联发布；部分创建保留记录，可按 UID 清理，模型 PVC 保留。
- 内部 Service 不承担平台 Key 认证，正式访问应经 MiniStation 网关。P/D 网络应只供可信工作负载访问；本功能不提供多租户网络隔离或路由器高可用。

## 验证与验收

本地 HTTP 合成上游覆盖 KV 交接、非流式及 SSE、最终 usage、缺失元数据、上游拒绝、超时、客户端取消、并发限制；它不执行模型计算。API 测试覆盖总配额、路由镜像策略、所有角色就绪、部分失败和清理。浏览器测试覆盖场景卡片、参数回填、自定义、请求内容和移动布局。

`node scripts/verify-distributed-cluster.mjs` 对 TP 和 PD 清单执行真实服务端 dry-run，不创建 GPU 工作负载。GPU 环境还必须验证镜像启动、模型和 tokenizer 一致性、真实跨节点 KV 传输、输出正确性、取消后的资源回收，并以相同请求集比较合并部署和 PD 的 TTFT、生成间隔、成功率与资源消耗。当前无真实 GPU 验收和性能最优认证。
